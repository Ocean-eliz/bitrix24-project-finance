# Project Finance for Bitrix24

Небольшое веб-приложение для ручного учёта доходов и расходов по проектам внутри Битрикс24.

## Что реализовано

- проекты с описанием и командой сотрудников;
- доходы и расходы по статьям;
- обязательные статьи из тестового задания:
  - доход от проекта;
  - внешние программисты;
  - внутренние программисты;
  - расходы на ИИ;
  - аренда сервера;
  - дивиденды;
- добавление собственных статей доходов и расходов;
- добавление нескольких сотрудников к проекту;
- карточка проекта с доходами, расходами, прибылью и рентабельностью;
- общий портфельный дашборд;
- совместная работа через единую SQLite БД на сервере;
- автоматическое определение текущего пользователя при запуске внутри Битрикс24;
- синхронизация сотрудников через `user.get` при наличии доступа Битрикс24;
- standalone/demo-режим для быстрой проверки без портала;
- Docker-запуск одной командой;
- unit-тесты финансовых расчётов.

## Финансовые расчёты

Денежные значения хранятся в БД **целым числом копеек**, а не `float`.

- **Доходы** = сумма всех операций по статьям типа `income`.
- **Расходы** = сумма всех операций по статьям типа `expense`.
- **Прибыль** = Доходы − Расходы.
- **Рентабельность затрат** = Прибыль / Расходы × 100%.
- Если расходов нет, рентабельность выводится как `—`, чтобы не допускать деления на ноль.

Расчёты выполняются на backend, поэтому клиент не является источником финансовой логики.

## Быстрый запуск

### Вариант 1 — Docker

```bash
docker compose up --build
```

Открыть: `http://localhost:8000`

### Вариант 2 — Python

Требуется Python 3.12+.

```bash
python -m venv .venv
# Windows
.venv\Scripts\activate
# macOS/Linux
source .venv/bin/activate

pip install -r requirements.txt
uvicorn app.main:app --reload
```

Открыть: `http://localhost:8000`

При первом запуске создаётся демо-проект. Чтобы стартовать с пустой БД:

```bash
APP_SEED_DEMO=false uvicorn app.main:app --reload
```

На Windows PowerShell:

```powershell
$env:APP_SEED_DEMO="false"
uvicorn app.main:app --reload
```

## Запуск внутри Битрикс24

Приложение подключает официальный `BX24.js`, ожидает `BX24.init`, получает текущего пользователя через `user.current` и при возможности список активных пользователей через `user.get`.

Для проверки внутри портала:

1. Развернуть проект на HTTPS-домене (Render/Railway/VPS и т.п.).
2. Создать локальное приложение в Битрикс24 и указать URL приложения на развернутый адрес.
3. Выдать приложению права на пользователей (`user`).
4. Открыть приложение из Битрикс24 — интерфейс будет загружен во фрейме, а текущий сотрудник синхронизируется автоматически.

Backend не выставляет заголовки, запрещающие открытие во фрейме, поэтому приложение можно встраивать в интерфейс Битрикс24. Для production-развёртывания политику `Content-Security-Policy` стоит настроить под конкретный домен портала.

> Для production-версии я бы добавил серверную проверку OAuth-токена Битрикс24, роли/права на проекты, PostgreSQL и журнал аудита. Для тестового задания текущая архитектура оставлена намеренно компактной и легко запускаемой.

## API

После запуска Swagger доступен по адресу:

`http://localhost:8000/docs`

Основные методы:

- `GET /api/projects`
- `POST /api/projects`
- `GET /api/projects/{id}`
- `DELETE /api/projects/{id}`
- `GET /api/categories`
- `POST /api/categories`
- `GET /api/employees`
- `POST /api/employees/sync`
- `POST /api/projects/{id}/employees`
- `GET /api/projects/{id}/transactions`
- `POST /api/projects/{id}/transactions`
- `DELETE /api/transactions/{id}`

## Использование ИИ

ИИ использовался как инструмент ускорения разработки: для первоначального проектирования структуры, чернового кода интерфейса/API и проверки граничных случаев. Результат проверялся вручную: финансовая логика вынесена на backend, добавлены unit-тесты, предусмотрено деление на ноль, суммы хранятся в копейках, а интеграция с Битрикс24 сверена с официальной документацией.
